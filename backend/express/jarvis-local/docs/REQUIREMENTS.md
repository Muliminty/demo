# Jarvis Local 需求总表

这份文档用于汇总 `Jarvis Local` 当前明确的全部需求，作为后续架构设计、模块拆分、数据库设计和开发排期的依据。

它和 [`PLAN.md`](/Users/muliminty/project/demo/backend/express/jarvis-local/docs/PLAN.md) 的区别是：

- `REQUIREMENTS.md`：说明“要做什么”
- `PLAN.md`：说明“按什么顺序做”

---

## 一、项目目标

`Jarvis Local` 的目标不是做一个普通聊天机器人，而是做一个运行在本机、长期陪伴式、可持续成长的个人 AI 助手。

核心方向：

- 本地优先
- 长期记忆
- 工具能力
- 知识检索
- 多渠道接入
- 插件化扩展
- 越用越懂用户
- 更像稳定的长期搭档

---

## 二、产品定位

### 1. 短期定位

第一阶段，它是一个本地 Web Chat AI 应用：

- 接入 Ollama
- 提供本地聊天体验
- 支持流式输出
- 支持会话管理

### 2. 中期定位

第二阶段，它会演进成一个具备：

- 记忆系统
- 工具系统
- 知识检索
- 任务协作能力

的本地个人助手。

### 3. 长期定位

长期目标是成为“电脑里的 Jarvis”：

- 像同一个人
- 能记住你和你的项目
- 能在多个渠道工作
- 能帮你做真实任务
- 会随着使用不断成长

---

## 三、核心产品需求

### 1. 聊天体验

必须具备：

- 本地聊天界面
- 多轮对话
- 流式输出
- 模型切换
- 新建会话
- 错误提示
- 基本思考过程展示

后续增强：

- 停止生成
- Markdown 渲染
- 会话列表
- 消息搜索
- 更自然的输入与回复体验

### 2. 拟人化体验

目标不是卖萌，而是“连续性”。

必须具备：

- 稳定人格
- 稳定语气
- 记得用户是谁
- 记得最近在做什么
- 能承接之前的项目进度
- 能根据用户偏好调整表达方式

后续增强：

- 更自然的称呼
- 长期关系感
- 主动提醒与回顾
- 有边界的情绪表达

### 3. 长期成长

必须具备：

- 根据长期使用积累偏好
- 根据项目推进积累上下文
- 根据反馈调整回答方式

后续增强：

- 反思系统
- 记忆去重与合并
- 偏好学习
- 长期行为模式总结

## 四、记忆系统需求

### 1. 设计目标

记忆系统不是“保存所有聊天记录”，而是要做到：

- 记住高价值信息
- 支持长期使用
- 支持按需提取
- 支持治理、编辑、删除

### 2. 记忆分层

必须支持以下层次：

#### Working Memory

用于当前会话短期上下文。

内容包括：

- 最近几轮对话
- 当前工具结果
- 当前任务临时上下文

#### Profile Memory

关于用户的稳定事实。

例如：

- 常用语言
- 技术栈
- 回答偏好
- 工作习惯

#### Relationship Memory

关于用户和 Jarvis 互动方式的长期偏好。

例如：

- 喜欢简洁直接
- 更希望先改代码再解释
- 不喜欢客服式口吻

#### Task Memory

当前项目与任务状态。

例如：

- 当前项目名
- 当前目标
- 当前卡点
- 最近进展

#### Episodic Memory

历史关键事件和里程碑。

例如：

- 某天第一次跑通某个功能
- 某次做出的重要架构决定

#### Reflection Memory

系统对“如何更好帮助用户”的总结。

例如：

- 用户更喜欢先做 MVP
- 用户对 UI 体验要求高于花哨功能

### 3. 记忆能力要求

必须支持：

- 记忆提炼
- 记忆读取
- 记忆写入
- 记忆删除
- 记忆更新
- 记忆去重
- 记忆优先级与置信度

### 4. 记忆治理要求

必须支持：

- 用户查看记忆
- 用户手动删除记忆
- 用户手动修改记忆
- 记录记忆来源
- 记录最后确认时间

## 五、工具系统需求

### 1. 设计目标

Jarvis 必须不止会回答，还要能“做事”。

### 2. 工具能力分层

#### 低风险工具

- 获取时间
- 读取文件
- 搜索项目
- 列目录
- 读取剪贴板

#### 中风险工具

- 创建笔记
- 修改白名单目录内容
- 执行预定义命令
- 打开应用

#### 高风险工具

- 任意 shell
- 删除文件
- 修改系统设置
- 发送外部消息

### 3. 工具系统要求

必须支持：

- 工具注册
- 工具 schema
- 工具调用日志
- 工具执行结果结构化
- 风险等级标注
- 权限确认机制

### 4. 工具调用体验

前端需要支持展示：

- 当前正在调用什么工具
- 工具参数
- 工具结果
- 工具失败原因

---

## 六、知识系统需求

### 1. 设计目标

Jarvis 不能只靠模型本身回答，必须能检索你的本地知识。

### 2. 支持的知识来源

后续应支持：

- Markdown 笔记
- 文本文档
- 项目代码
- 配置文件
- 本地知识目录
- 聊天摘要

### 3. 知识系统能力

必须支持：

- 文件导入
- 文本切块
- metadata 建立
- 本地检索
- 回答前注入相关上下文

### 4. 检索阶段

建议分阶段：

- 第一阶段：关键词 / SQLite FTS
- 第二阶段：embedding / 向量检索

---

## 七、多渠道接入需求

### 1. 设计目标

Jarvis 不能只服务于 Web UI，还要能够接入外部聊天与工作渠道。

### 2. 预期渠道

后续应支持：

- Web Chat
- 飞书
- Telegram
- Discord
- 其他工作聊天入口

### 3. 渠道层要求

系统应支持：

- 不同渠道的消息接入
- 不同渠道的消息标准化
- 会话路由
- 渠道回复适配
- 渠道级权限控制

### 4. 飞书场景要求

后续飞书接入至少要支持：

- 飞书私聊
- 飞书群聊
- 群聊中仅在 `@Jarvis` 时响应
- 群聊绑定项目上下文
- 渠道身份映射

---

## 八、插件系统需求

### 1. 设计目标

Jarvis 必须是可扩展系统，而不是写死的一体应用。

### 2. 插件类型

必须支持两类插件：

#### Capability Plugins

为系统增加能力：

- 模型提供方
- 工具提供方
- 记忆提供方
- 知识提供方

#### Channel Plugins

为系统增加通信入口：

- Web
- 飞书
- Telegram
- Discord

### 3. 插件能力要求

必须支持：

- manifest
- 权限声明
- 生命周期 hook
- 隔离存储
- 插件日志
- 插件启停

### 4. 插件治理要求

必须支持：

- 默认零权限
- 显式权限申请
- 高风险权限确认
- 插件独立配置
- 插件异常隔离

## 十、数据与存储需求

### 1. 存储目标

必须支持：

- 本地优先
- 可备份
- 可迁移
- 可调试
- 支持后续扩展

### 2. 推荐存储方式

建议采用：

- SQLite：结构化数据、索引、会话、日志
- JSON / JSONL：稳定配置与事件流
- 本地目录：知识文件、插件数据

### 3. 存储内容

后续应支持保存：

- sessions
- profile memory
- relationship memory
- task memory
- episodes
- reflections
- knowledge chunks metadata
- tool logs
- plugin registry
- channel mapping

## 十一、权限与安全需求

### 1. 权限目标

Jarvis 本质上会接触本地文件、系统命令、外部渠道，因此必须有权限体系。

### 2. 必须支持的权限能力

- files.read
- files.write
- memory.read
- memory.write
- tools.execute.safe
- tools.execute.dangerous
- shell.exec
- channel.send
- knowledge.index

### 3. 安全要求

必须支持：

- 高风险操作确认
- 渠道级权限限制
- 插件级权限限制
- 用户级权限限制
- 工具执行日志
- 错误可追踪

## 十三、技术栈需求

### 当前阶段

可以保留轻量实现：

- Node.js 原生 HTTP
- 原生 HTML / CSS / JS
- Ollama REST API

### 正式演进建议

- Frontend: React + Vite + TypeScript
- Backend: Node.js + Express + TypeScript
- Database: SQLite
- Search: SQLite FTS
- Later: 向量检索
- Desktop Shell: Tauri（后期）

## 十七、验收标准

什么时候可以说第一阶段“Jarvis 雏形”成立？

至少满足：

- 能稳定本地聊天
- 能记住用户基础信息
- 能记住当前任务状态
- 能调用至少 3 个低风险工具
- 能从本地知识源检索信息
- 有基础权限和日志

什么时候可以说“多渠道 Jarvis”成立？

至少满足：

- Web Chat 正常
- 飞书私聊正常
- 飞书群聊按规则响应
- 渠道间用户身份可映射
- 渠道级权限可控制
