# 6. 非功能需求与技术架构 (Non-Functional & Technical Specs)

## 6.1 Token 成本与性能优化策略
在完全交由 LLM 驱动多智能体的架构中，API 的调用成本与并发限流是核心痛点。

*   **时间切片心跳机制**：
    *   **问题**：不能让所有 NPC 每秒都去请求 LLM。
    *   **方案**：采用大周期的调度循环。将一天分为少数几个主要节点（晨间规划、午休、傍晚、午夜总结）。只在这些时间点触发 LLM 生成全局的行为队列，前端再花几分钟至几十分钟慢慢去播放这些行为。
*   **上下文 (Context) 严格瘦身**：
    *   每次对话只传入：`基础人设 prompt` + `向量检索出最相关的 1-3 条核心记忆` + `最近 10 次的动作日志流` + `当前环境信息`。
*   **模型分级策略**：
    *   日常生活的小型对话、路径决策 -> 廉价模型（如 DeepSeek-V3 / GPT-4o-mini）。
    *   深夜总结反思、基因突变判定、复杂情感信仰的推理 -> 聪明但昂贵的模型。

## 6.2 技术栈选型参考

| 模块 | 推荐技术方案 | 作用说明 |
| --- | --- | --- |
| **前端视觉层** | Phaser 3 / PixiJS | 成熟的 2D WebGL/Canvas 像素渲染引擎 |
| **前端 UI 层** | React + Zustand / Tailwind | 负责包裹游戏画布外的留言板、日志流和面板界面 |
| **后端调度层** | Node.js (BullMQ) or Python (Celery) | 管理数千个并发的时间切片任务与消息队列 |
| **AI 推理引擎** | OpenAI / Claude / DeepSeek API | 角色的“大脑中枢” |
| **关系型数据库** | PostgreSQL / SQLite | 存储角色基础档案、历史记录、家族关系树 |
| **向量数据库** | ChromaDB / Pinecone / Qdrant | 实现角色“深度记忆”的语义检索与存取 |
| **前后端通讯** | WebSocket / Socket.io | 实时向客户端推送角色的像素坐标和内心日志流 |
